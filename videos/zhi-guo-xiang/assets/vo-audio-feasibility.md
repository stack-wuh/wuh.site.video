## 〇、结论先说（4 条）

1. **时间预算不是瓶颈**。21 条共 239 个汉字，@4.2 字/秒 = 56.9s（与既有「约 57s」口径吻合〔析〕）；21 个窗口**没有一条装不下**。4.2 基准下最紧的是 S31/S35，各余 0.80s；换成现实口播语速 3.68 字/秒（由已定稿的 8 落点 24.7s 反解〔析〕），S31/S35 压到 0.23s 余量（临界），另有 6 条进「紧」区。**结论：能念完，但余量薄，不允许临场加字。**
2. **真正的阻塞不是时间，是两处结构问题**：① 男声 21 条与**已定稿的诗六行**在 4 处硬重叠（S31×L1/L2、S35×L4、S37×L5、S38×L6）；② 21 条里有 **12 条**压在 BGM 平均 > −20dB 的段上〔实〕，占人声总时长 73%〔析〕——**必须 ducking**。
3. **ducking：技术上可行，但有条件**〔判〕。侧链压缩能塞进**单级 `amix=inputs=3`**（绕开「两级 amix 截到 143.45s」的坑），参数存在解析解，压低深度 12.7–16.7dB 可达 −24/−28dB 目标。代价是**烟花与寻路两处高潮会被压 13–15dB**，这是审美让位，不是技术问题。
4. **建议路径**：先做降级梯 **L1（sidechain）**，若高潮被压得听不下去 → 直接跳 **L3（缩句）** 或 **L4（只念关键 N 条）**，不要硬调参数。**L5（回退 8 落点）永远是安全出口**——那版已经拼好、已经验过。

### 1.1 口径

- 字数只数**汉字**（不含标点）〔析〕。
- 估时 = 汉字数 / 语速 + 标点停顿（逗号 0.20s、句号 0.35s、`~` 0.40s）〔析〕。
- **有效口播窗 = 窗长 − 0.6s**（进 0.3s 起音、出 0.3s 收尾，避免贴字幕出入）〔判〕。

### 2.5 顺手发现：§八 有一处自相矛盾

`script-v9.md` §八 把「151.0–163.0 / 掌心→拈针」标成「**安静地回来**」，但同一份文档的曲形表写「**26–60s 第二遍陈述，加一层**」，`music.md` §七 也写「第二遍从 45.46s 起」〔实〕。曲 45.46–57.46 落在「30–47 回落(−22)」与「47–60 平稳(−17)」上，**推算平均 −17.8dB，不是安静段**〔析〕。

后果：S25（151.0–157.0）被当成「踩谷」写进了对位表，实际它压在 −17.8dB 上，属于要压的 12 条之一。**这是对位表里的一个标签错误，不是时间轴错误**——建议改成「主题第二次（中平）」。同源的 S27（163.0–170.0）也被标成安全，实际 −14.4dB。

> 真正的安静段只有三处，且都已被人声避开：**11–23s、144–151s（断点静默）、157–163s**。这三处正好是 ducking 的天然**对照静音段**，见 3.5。

## 三、ducking 方案

### 3.1 先避开那个已实证的坑

`mux-bgm.mjs` 现在的口径〔实〕：BGM 两遍各 `volume=0.7` → `adelay` → 与 `aformat` 对齐的人声轨走**单遍** `amix=inputs=3`。文档记的坑：**先合 BGM 再叠人声的两级 amix 实测把音轨截到 143.45s**（第二遍 BGM 根本没参与）〔实〕。

直觉上做 ducking 就得「先合 BGM 再压再叠人声」＝两级 amix，正好踩坑。**绕法：对两遍 BGM 分别做侧链压缩，压完再和以前一样单遍 amix=3。** 拓扑与已验通的版本同构，只多了两个 `sidechaincompress`。

### 3.2 可直接抄的滤镜链〔析〕

```bash
ffmpeg -y \
  -i <film-silent>.mp4 -i <aiyi.mp3> -i <voice-track-full.wav> \
  -filter_complex "\
[1:a]atrim=0:139.46,asetpts=PTS-STARTPTS,afade=t=in:st=0:d=1,volume=0.7[b1];\
[1:a]atrim=45.46:139.46,asetpts=PTS-STARTPTS,afade=t=in:st=0:d=1,volume=0.7[b2];\
[2:a]aformat=sample_fmts=fltp:sample_rates=44100:channel_layouts=stereo,asplit=3[vk1][vk2][vc];\
[vk1]atrim=4:143.46,asetpts=PTS-STARTPTS,aformat=sample_fmts=fltp:sample_rates=44100:channel_layouts=stereo[k1];\
[vk2]atrim=151:245,asetpts=PTS-STARTPTS,aformat=sample_fmts=fltp:sample_rates=44100:channel_layouts=stereo[k2];\
[b1][k1]sidechaincompress=threshold=0.0182:ratio=8:attack=15:release=280:knee=2.5:link=maximum:detection=rms:makeup=1:level_sc=1:mode=downward[du1];\
[b2][k2]sidechaincompress=threshold=0.0182:ratio=8:attack=15:release=280:knee=2.5:link=maximum:detection=rms:makeup=1:level_sc=1:mode=downward[du2];\
[du1]adelay=4000|4000[d1];\
[du2]adelay=151000|151000[d2];\
[d1][d2][vc]amix=inputs=3:duration=longest:dropout_transition=0:normalize=0[a]" \
  -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k -movflags +faststart -shortest out/<final>.mp4
```

**四处关键，抄的时候别漏**〔析〕：

1. **key 必须是「与该遍 BGM 同一 0 基时间轴」的切片**。`[vk1]atrim=4:143.46` 把绝对 4.0 挪到 0，才和 `[b1]`（曲 0 起）对齐；`[vk2]atrim=151:245` 把绝对 151.0 挪到 0，才和 `[b2]`（曲 45.46 起）对齐。**如果直接用整条人声当 key，第二遍的侧链会整体错 106.54s，全片压反。** 这是本方案最容易错的一步。
2. **`sidechaincompress` 的压缩量只跟 key 电平有关，跟 BGM 电平无关**。所以人声静默时 key 低于阈值 → 增益零变化 → **安静的段落不会被误压**，不需要额外的 `enable` 开关。
3. **`release=280`** 直接对应「人声静默 300ms 内恢复」的验收线（留 20ms 余量给检测窗）。
4. **仍然只有一级 `amix=inputs=3`**，且 `duration=longest` + 人声轨自带 245s 静音底 → 结构上不可能再被截到 143.45s。

### 3.3 参数与反解

`sidechaincompress` 的压力量公式〔析〕：

```
深度(dB) = (key电平dB − threshold dB) × (1 − 1/ratio)
```

已知：目标深度、人声 RMS → **可直接反解 threshold**，不用试参数：

```
threshold_dB = voiceRms_dB − 目标深度 / (1 − 1/ratio)
```

| 参数 | 取值 | 取值理由 |
|---|---|---|
| `threshold` | **0.0182（−34.8dB）** | 按人声 −18dB、目标压 14.7dB、ratio=8 反解；`--mode measure` 会用**实测**人声 RMS 重算 |
| `ratio` | **8** | 8:1 足够做出「音乐明显退后」的台阶；再高会把起伏压平 |
| `attack` | **15 ms** | 在第一个音节爆出前就位；>30ms 会让句首「漏一小截音乐」 |
| `release` | **280 ms** | 验收线 300ms 恢复；>300 会拖进下一句 |
| `knee` | **2.5 dB** | 软膝，避免尾音处硬跳变（pumping 的主要来源） |
| `makeup` | **1（不补）** | 补回来等于白压 |
| `level_sc` | **1** | 人声电平正常时留 1；若实测人声偏低（< −30dB）设 2，否则 threshold 会掉到 0 附近失去意义 |
| `link` | **maximum** | 立体声两声道同步压，避免声像右移 |
| `detection` | **rms** | 比 peak 平滑，不容易被口水音误触发 |
| `mode` | **downward** | 默认，就是要压 |

**基线参数（人声按 −18dB 估）**〔析〕：

| 目标 | 需压最深 | threshold | 线性值 |
|---|---|---|---|
| 只到硬底线 −24dB | 12.7 dB | −32.5 dB | 0.0237 |
| **建议 −26dB** | **14.7 dB** | **−34.8 dB** | **0.0182** |
| 苛刻 −28dB | 16.7 dB | −37.1 dB | 0.0140 |

**为什么建议 −26 而不是任务书里的 −24**〔判〕：−24dB 只是「不糊」的下限。人声如果按 −18dB RMS，BGM 在 −24 时信噪比只有 6dB，中文辅音会被吃掉。**−26 ~ −28 才是听清的门槛**；而 ffmpeg 侧链是拿电平做乘法，不区分段落，所以要注意一个副作用：

> ⚠️ **副作用（必须知道）**：安静段（如 −31dB 的「走到无声」）也会被同样压 14.7dB → −45.7dB，等于音乐彻底消失。这些段落本来就听不见，**无害**；但**回落谷（−21dB）会被压到 −35.7dB**，而回落谷是 v9 故意留给音乐呼吸的地方（S14「她不知道」整句压在那八秒上）。**结果是：这句旁白念的时候，音乐确实退到底了。** 这是 ducking 的本质代价。

### 3.4 预期压低量与审美代价

逐条所需深度（到 −26dB 目标）〔析〕：

| 镜 | 段平均 dB | 需压 dB | 镜 | 段平均 dB | 需压 dB |
|---|---|---|---|---|---|
| S16 | −11.3 | **14.7**（最深） | S35 | −15.1 | 10.9 |
| S18 | −13.1 | 12.9 | S19 | −15.5 | 10.5 |
| S11 | −13.2 | 12.8 | S10 | −17.0 | 9.0 |
| S28 | −12.9 | 13.1 | S30 | −17.2 | 8.8 |
| S27 | −14.4 | 11.6 | S25 | −17.8 | 8.2 |
| S05 | −18.0 | 8.0 | S36 | −19.3 | 6.7 |

**代价清单**〔判〕：

1. **烟花高潮（绝对 64–77s）被压 12.8dB**。这是全片第一次大高潮，`script-v9` §六 写的是「满城炸开，火金铺满夜空」。S11「那一夜，满城烟花是为她放的。」念在这上面——**画面上是最大的一场戏，音乐被压到最低。** 这是本方案最大的美学风险。
2. **背剑出门 / 寻路（绝对 94–113s）被压 12.9–14.7dB**。这是第二次最高潮，同样被压。
3. **回落谷的呼吸被压掉**（见 3.3 副作用）。
4. 累计：**41.5s 的音乐处于被压状态**，占全片 17%，且高度集中在这三处高潮。

### 3.5 怎么验证（这是本任务的核心交付）

**不能只量成片**——成片里人声和 BGM 混在一起，量不出「BGM 被压了多少」。必须渲染**三份**，逐窗比〔析〕：

| 代号 | 内容 | 用途 |
|---|---|---|
| **A** `mix.mkv` | ducked BGM + 人声 | 成片音轨、终验 |
| **B** `duck-B.wav` | **只**有 ducked BGM（人声不进 amix，只当 key） | 量「压低后」电平 |
| **C** `duck-C.wav` | **只**有未压低 BGM（只有 `volume=0.7`） | 量「压低前」电平 |

`压低深度 = C − B`。**同一窗口、同一条 BGM、差一个 ducking → 与人声电平完全无关**，所以不会被 TTS 响度污染。脚本一条命令出三份 + 自动判四条：

```bash
node scripts/duck-voice.mjs --mode all \
  --film <film-silent>.mp4 --audio <aiyi.mp3> \
  --voice <voice-track-full.wav> --out out/duck/mix.mkv
```

**判据（写死在脚本 RULES 里）**：

| # | 判据 | 阈值 | 为什么 |
|---|---|---|---|
| 1 | 人声窗内 BGM ≤ 硬底线 | **−24 dBFS** | 不糊 |
| 2 | 人声窗内 BGM 建议值 | **−26 ~ −28 dBFS** | 中文辅音可懂 |
| 3 | 压低深度区间 | **8 – 20 dB** | <8 压不住；>20 音乐会塌（=降级信号） |
| 4 | **对照静默窗误压** | 深度 **≤ 0.5 dB** | 人声为零处不该有任何动作 → 验证 key 对齐没错 |
| 5 | **恢复时间** | 窗口末后 **200–300ms 段**与 C 差 **≤ 1.5 dB** | 对应「人声静默 300ms 内恢复」 |
| 6 | 时长 | **245.0s** | 防两级 amix 截断复发 |
| 7 | 帧数 | **7350** | 对 `script-v9` §九 |
| 8 | 音轨规格 | **44100Hz / 2ch / aac 192k** | 与 BGM 源一致 |

**对照静默窗用哪三段**：`11–23s`、`144–151s`、`157–163s`——§七 明确写了这三处人声为零〔实〕。**判据 4 是本方案的自检阀**：如果 key 的 `atrim` 起点写错（3.2 第 1 点），这三点会出现 10dB 量级的误压，一眼就抓出来。

**听感判据（必须戴耳机过一遍，脚本量不出来的）**〔判〕：

1. **句首不抢**——每个落点的第一个字之前，音乐已经退下去了，没有「音乐先撞一下再退」的抽吸感。
2. **句尾不拖**——最后一个字收完后，音乐在 0.3s 内回来，没有长时间发闷。
3. **长句中间不呼吸**——S31/S35 这种 17 字长句，中间的逗号停顿（0.2s）不足以让音乐弹回来再压下去；若听到「一鼓一鼓」的呼吸感，说明 `release` 相对逗号停顿太短，要加到 300–350ms 并同步放宽验收窗口（或改用 L3 缩句）。
4. **高潮段不塌**——64–70s（烟花）与 94–99s（寻路）这两处，音乐被压之后仍然应该是「有质感的背景」而不是「一条嗡嗡的低频」。若塌了 → 降级梯 L2（只压中频）。
5. **人声与诗行衔接自然**——S30 结束（189.0）到 L1 起（189.0）之间没有任何空隙，两句不同声源叠着交接，**这是最容易露馅的位置**：若听到男声尾音和女声首音互抢，说明男声 S30 需要提前 0.2s 收。
6. **A/B 对比盲听**——用同一段（如 94–99s）分别听 A 与 C，判断「压了之后是变清楚了，还是变单薄了」。**如果分不清哪个更清楚，说明 ducking 白做，直接砍旁白。**

### 3.6 ducking 结论

**技术可行 / 但它不是免费的**〔判〕。

- **可行**〔析〕：滤镜链结构确定（单级 amix=3 绕开截断坑）、参数有解析解、验证方法可量化、参数深度的上限 14.7dB 在合理范围（<20dB）。
- **需三个条件**〔判〕：
  1. **先砍掉 S31/S35 男声**（1.4 的硬重叠），否则「两路男声叠在一条诗行上」，ducking 参数怎么调都救不了。
  2. **接受高潮段音乐让位**（3.4 的代价 1、2）。这一条要用户点头——`script-v9` §八 的三条暗线里有一条是「她越靠近，音乐越远」，ducking 恰好强化了这个意图，**但烟花高潮被压是反过来的**。
  3. **必须在本机实测校准**（本报告全部 dB 都是〔析〕）。三条：`--mode measure` 出人声实测值 → `--mode render` 出 A/B/C → `--mode verify` 过 8 条判据。
- **不可行的情形**〔判〕：若实测发现**人声 RMS 低于 −30dB**（近讲真声没做归一化时很容易），反解出的 threshold 会掉到 −50dB 附近，此时任何音乐都触发满压，**ducking 退化成「人声一响音乐就消失」**。这种情况下不要调参数，直接走 L3/L4。**这就是「ducking 验不通」的最现实形态。**

## 四、降级梯

从最轻到最重。**每级都写清了「什么时候跳到这一级」**〔判〕。

### L0 · 先试：手工 volume 包络（不压，直接编排）

**做法**：落点表是已知的、固定的 245s 时间轴，不需要靠电平检测——直接用 `volume` 表达式按窗口写死增益，用 3 帧斜坡过渡。

```bash
# 示意：人声窗口内 BGM 降 0.18(−15dB)，其余 1.0。斜坡用 volume 的 eval=frame + 线性插值
[1:a]volume='if(between(t,23,29),0.18, if(between(t,58.4,63.6),0.18, ...))':eval=frame
```

- **成本**：改 `mux-bgm.mjs`（不允许）→ **只能写进 `duck-voice.mjs`**，或在 `--mode render` 里加一个 `--envelope` 分支。半天。
- **代价**：换掉侧链后**没有电平自适应**，需要把 21 个窗口手抄进表达式（易错）；窗口边界硬，靠斜坡掩盖。**好处是确定性 100%，不依赖人声电平**，也完全不会误压。
- **建议**：**如果实测人声电平不稳（3.6 的不可行情景），L0 比 L1 更靠得住。** 我把它排在 L1 前面是因为它成本更低、结果更可预测。

### L1 · 主方案：sidechaincompress（第三节）

- **成本**：0 行改现有代码，跑 `duck-voice.mjs --mode all` 一条命令，看 8 条判据。
- **代价**：3.4 的四条审美代价；需要人声电平正常（−14 ~ −22dB RMS）。
- **跳到下一级的条件**：判据 3（深度 >20dB）、或听感判据 4（高潮塌）、或 3.6 的不可行情景。

### L2 · EQ 避让：只压人声频段（200Hz–4kHz）

**做法**：ffmpeg **没有原生动态 EQ**，但可以拆频段实现——把 BGM 拆成低/中/高三段，**只对中频段侧链压缩**，再合回来：

```bash
[b1]asplit=3[b1l][b1m][b1h];
[b1l]lowpass=f=200[bl];
[b1m]highpass=f=200,lowpass=f=3500[bm];
[b1h]highpass=f=3500[bh];
[bm][k1]sidechaincompress=threshold=0.02:ratio=10:attack=15:release=280[bm2];
[bl][bm2][bh]amix=inputs=3:normalize=0[b1out]
```

- **成本**：每条 BGM 从 1 路变 4 路，filtergraph 体积 ×3；分频点的相位/增益补偿要试（`lowpass`+`highpass` 串联不是完美互补，200/3500Hz 处会有 ±1.5dB 起伏）。
- **代价**：**低频与高频完全保留** → 高潮的鼓点与弦乐高频还在，**音乐的「体感」保住了，但人声的辅音区（2–4kHz）让出来**。听感上音乐更「闷」但更「在」。
- **性价比**：**这是最值得试的一级**。人声可懂度主要靠 1–4kHz，而音乐的情绪重量在低频。用 3–6dB 的中频让位，往往比全频压 12dB 效果好。
- **触发**：L1 判据 4 失败（高潮塌）时优先来这一级，而不是 L3。

### L3 · 缩句到窗口一半

**做法**：把 12 条 > −20dB 的条目各砍一半字数（17 字 → 8–9 字），使**压得最深的那几条（S11/S16/S18/S28）时长减半**，ducking 占空比下降。

- **成本**：重写 12 条文本 + 重走一次审稿（task-1/task-2 的裁决全部要重做）+ 重新 TTS/录音。**约 1.5 人日 + 一轮审稿。**
- **代价**：**内容损失**。这些条目每一句都在 v9 的检验标准下通过了「删掉就少知道一件事」；砍一半必然丢掉一件事。
- **副作用（好的一面）**：sentence 变短 → 占空比下降 → 可以被压的窗口变短，`release` 也有空间了。S31/S35 的 0.23s 临界问题一并解决。
- **推荐用于**：**只砍 S11 / S16 / S28（三条压 12.8–14.7dB 的）**，其余保留原句。这是 L3 的性价比最优解。

### L4 · 只念关键 N 条

**做法**：回到「旁白是加分项，字幕是基本盘」。只念落在音乐谷/尾奏里的、本就安全的条目。按 2.3 表，**安全窗口的条目是 9 条**：S01 / S04 / S14 / S20 / S22 / S23 / S31 / S37 / S38。

- **与审稿呼应**：task-2（`vo-review-v1.md`）必须交出「只保留 5 条留哪 5 条」的反方意见。**我的音频侧给出的 9 条是一张「零 ducking 成本清单」，可以直接和审稿的 5 条取交集。** 交集若为 5–6 条，那就是最省事的落地方案：**ducking 完全不需要做**，回到平叠。
- **成本**：删 15 条稿（但那些稿本来就要写，沉没成本）；TTS/录音量从 21 条降到 5–9 条。
- **代价**：**回到 v9 原本的设计意图**——「字幕=事实」。这不是失败，是回到 v9 §二〔判〕。
- **注意**：S31 在安全窗口里（−20.3），但它和诗行 L1/L2 硬重叠 → **实际可用清单是 8 条：S01 / S04 / S14 / S20 / S22 / S23 / S37 / S38**。

### L5 · 回退双声部 8 落点（安全出口）

- **成本**：**零**。`voice-track-full.wav` 已拼装、已验（8 落点有声 / 对照区 RMS=0）〔实〕，`mux-bgm.mjs --voice` 已验通〔实〕。
- **代价**：放弃 21 条全铺这个目标。
- **何时用**：L0–L4 全部验不通，或用户不想再花时间。**任何时候都可以无损退回这里。**

### 成本对照

| 级 | 工作量 | 内容损失 | 技术风险 | 需要谁定 |
|---|---|---|---|---|
| **L0** volume 包络 | 半天 | 无 | 低（确定性） | 无 |
| **L1** sidechain | 1 小时（跑脚本） | 无 | 中（依赖人声电平） | 无 |
| **L2** EQ 避让 | 1 天（调分频） | 无 | 中 | 无 |
| **L3** 缩句 | 1.5 人日 + 1 轮审稿 | **中**（丢事实） | 低 | **用户 / 编剧** |
| **L4** 只念 N 条 | 0.5 天（删稿） | **大**（回到 v9 原设计） | 低 | **用户** |
| **L5** 回退 8 落点 | 0 | **大**（放弃目标） | **零** | **用户** |

## 五、执行清单（本机跑）

## 七、附录

### A. 字数口径

只计汉字（`[\u4e00-\u9fa5]`），标点不计字数但计停顿。例：S31「她留下一首诗，写的是十六岁那年的烟花。」= 6 + 11 = **17 汉字**，标点 `，`×1 + `。`×1 → 停顿 0.55s。21 条合计 **239 汉字**，@4.2 = **56.9s**（与既有「约 57s」口径吻合〔析〕）。

### B. 曲位置与 mp3 取样区间换算

| 绝对时间 t | 落在 | 曲位置 | 对应 mp3 区间（直接量 mp3 用电） |
|---|---|---|---|
| 0 – 4.0 | 片头 | — | 静音 |
| 4.0 – 143.46 | 第一遍 | t − 4.0 | [t−4.0, t−4.0] |
| 143.46 – 151.0 | 断点 | — | 静音 |
| 151.0 – 245.0 | 第二遍 | 45.46 + (t − 151.0) | 同左 |

`duck-voice.mjs` 的 `toScore()` / `scoreToMp3()` 实现了这两个公式；`--mode measure` 就是拿它们去量 mp3。

### C. 复算方式

本报告所有〔析〕数字可用一条命令复现：

```bash
node scripts/duck-voice.mjs --mode plan
```

输出：21 条时间预算（4.2 与 3.68 两档）、男声 vs 诗行重叠表、推荐参数、以及两条 filter_complex（ducked 与 plain）。
