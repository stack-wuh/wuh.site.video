**⚠ 访问量异常核实（10,760 → 5,440，必须读，防剧本引用错数）**

- **结论：口径重置，不是「修好后把历史重算了一遍」；历史访问量不可恢复（除非有 DB 备份）。**
- 证据链：
  1. `[API]` `/api/about/activity` 里 `visits` **最早一天 = 2026-08-17**；2026-08-16 及之前全部为 0（2025-12、2026-03~07 的月度合计只剩 `githubContributions`）。2026-08-17 恰好是 2026-11-14 往前 **90 天窗的起点**。
  2. `[git]` 2026-11-13 commit `4c6447c`（#587「审计 #568 批次 5」）：`visit_records` 新增 **TTL 90 天** `expireAfterSeconds` 索引（记录只服务 30 分钟去重窗与「今日」统计）、total 语义迁移到 `visit_stats.global.total` 计数器、新增 `backfill-visit-total.mjs` 幂等迁移存量（计数器缺位时以当前 `count` 兜底初始化）。
  3. `[git]` 2026-11-13 commit `5adeeb4`（#588）：`VisitStatsTotal` schema `_id` 显式 `String`——修 v1.4.104 上报端点 500（`_id:'global'` 被 mongoose cast 成 ObjectId 抛 CastError）。即「修 500」与「total 变小」是两件事：500 修的是**上报**，5,440 是 **TTL 裁剪 + 计数器初始化** 的结果。
  4. `[API]` v3 快照 2026-07 活动 5,744（visits 主导）→ v4 同月仅 **322**（纯 GitHub 贡献），交叉印证旧 visit_records 已被 TTL 清空。
- 算术：10,760 − 5,440 = **5,320** ≈ 2026-08-16 及之前的访问量。`/stats total` 5,440 与 activity 窗口 `visits` 合计 5,408 差 **32**（计数器初始化时点与窗口聚合的时点差）；`/stats today` 28 与 activity 2026-11-14 visits 43 亦不同源。
- **给剧本的口径**：凡引用访问量，写「**近 90 天访问 5,440**」或改用不受 TTL 影响的 **文章阅读总量 26,948**（144 条 Issue 的 `viewCount` 合计）。不要写「全站总访问 5,440」，那是错的。
