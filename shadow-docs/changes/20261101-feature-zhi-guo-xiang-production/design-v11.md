## 一 · 字幕跟着旁白与 BGM 走（意见 1）

### 1.1 病在哪

v10 的字幕是**手工写死在每个镜头里**的 `<Caption text start end>`，与旁白毫无关系，三处硬伤：

1. **口径打架**：S10 字幕写「说可以许三个愿望」，旁白 v7 已按原著改成「凭针可以差他办三件事」——观众先听到 A 再看到 B；
2. **落点打架**：字幕在镜头静默区里独自淡入淡出，旁白说话时字幕可能已经消失（S13/S18/S22 有 1–3s 的错位）；
3. **BGM 打架**：旁白退场、BGM 抬到「站出」的段落，字幕还在，夺走空镜的呼吸。

### 1.2 改成什么

**字幕成为旁白的可视化**，不是独立图层：

- **落点由旁白实测时间反推**：`out/voice/cues-v7.json`（audio 交付）里每条配音的实测 `start/end`（秒）→ 换算成帧 → 落到该镜头帧坐标：`start = voStart − shotAbsStart − 2f`（比人声早 2 帧起，避免"先见字后出声"），`end = voEnd + 18f`（收字比人声晚，留余韵）。
- **安全窗一律夹紧**：`start ≥ inSide + 12`、`end ≤ dur − outSide − 12`（inSide/outSide 是 v11 墨洇单侧帧数，见 §二）。夹到越界就**缩字**而不是越界。
- **两类字幕**（`scripts/captions.mjs` 自动判定）：
  - **跟人声字幕**（12 条）：落点跟旁白实测起落，`start = voStart−2f`、`end = voEnd+18f`；一镜多句时只跟第一句，不拖到下一次叙事上。
  - **BGM 点睛字幕**（9 条：S11/S14/S16/S22/S28/S31/S35/S37/S38）：旁白让位、BGM 抬到「站出」的段落，字幕自己扛一个意思；起落跟乐句（`inSide+16` → `dur−outSide−24`），停留比跟人声的字幕更久。
- 诗六行（`voice='poem'` 的 6 条配音）**不参与字幕锚定**：诗是纸上的字本身，由画面承担，不再在底部重打一遍。
- **文案与旁白同口径**：字幕文案以 `vo-script-v7.md` 为准；凡是字幕与旁白说法不同处（S10「三个愿望」→「差他办三件事」；S25「三个愿望，她用掉了一个」→「三枚针，她只用了一枚」），以旁白为准改字幕。
- **动画统一**：淡入 10f + 上浮 2px，淡出 12f；字距 0.08em 不变；暗底纸白、亮底墨色（`tone`）不变；**字幕层永远在墨洇遮罩之上**，转场时不跟着被墨吞（字幕是纸上的字，不是镜头里的事）。

### 1.3 实现

- 新增 `scripts/captions.mjs`：读 storyboard 字幕列 + `out/voice/cues-v7.json` + `shots-manifest.json` → 生成 `videos/zhi-guo-xiang/shots/caption-cues.ts`（`Record<shotId, { text, start, end }>`）；`shots.mjs check` 增加一条校验：字幕不出安全窗、字幕文案与 cues 的旁白文本不冲突。
- `components/Caption.tsx` 增 `shot` 属性：`<Caption shot="s10" />` 直接查表；老的 `text/start/end` 写法保留兼容（老单元在用）。
- 全片 14 条字幕的调用点由 Lead 统一扫一遍替换（避免与各镜重构冲突）。

## 二 · 转场统一为墨色晕开全屏（意见 2）

v10 有四种转场（纸翻/飞白/墨洇/硬切），用户只留一种：**墨色晕开全屏**。

- `ink` 升级为真正的全屏墨色擦除：3–5 团不同相位墨团、有机边缘、纸纤维渗点；吞没达实墨 `#2A2622`，露出像墨在纸上化开。单侧 **20f**（旧 12f）。
- 全部镜间转场改 `墨洇`，只保留 5 处**硬切**，理由都是"动作同步点，擦一下就废了"：
  `S10→S11`（掌心金针→城头烟花，硬切是"抬头"）、`S19→S20`（雪垭→醒木落下，硬切是那一击）、`S23→S24`（童谣→茶棚，硬切接锣响）、`S24→S25`（茶碗→掌心，同机位特写）、`S26` 入场（她拈针的静）。
- `S01` 入场仍为切；`S38` 出片接片尾仍为切。
- 转场仍在镜内占用，`durationFrames`/`startFrame` 一律不动。

## 三 · 逐镜重做

### 3.1 S09「她没看见他的脸」——从"重复的背影"改成"她的视点"

**问题**：S08 与 S09 都是他走开的背影，观众读作同义反复；雕影与空袖这两个信息点没有落在"她在看"上。
**改**：拆成前后景两层——
- 前景（实焦、暗部）：她的侧后仰视剪影占画面左侧 1/4，眼神方向朝右上；
- 背景（压暗、虚化）：`p-sleeve` 的背影与空袖缩小退到右侧中景；
- 天空：大雕影子以低透明度掠过（8f 一次，2 次），并在她瞳孔位置叠一枚 ≤3px 火金反光点（同一帧他影恰在瞳孔内 = 观众自己看见"她看见了"）；
- 收尾 30f：她的侧影淡出一半、只留瞳孔与雕影，接 S10 的掌心。
**验收**：抽 4 帧（前/中/雕影过瞳孔/收尾），任何一帧都不能再被读作"S08 复制"。

### 3.2 S10「三枚金针」——从静物摊掌改成递针动作

**问题**：v10 只是"她的掌摊开 + 三枚针在那里"，没有"给"的动作，也没交代谁给的。
**改**（180f）：
- 0–45f：她的手掌在前景摊开（`p-giving-hands` 的下半部），背景虚焦；
- 45–105f：**他的宽袖手从画面上方进入**，掌心向下，三枚金针一枚一枚落下（间隔 12f，落下 8f/枚，带轻微旋转与反光），每落一枚她的手指收一分；
- 105–150f：他的手退出画面上方（6f 内加速离去），她的手指合拢、针被握住；
- 150–180f：掌微收、灯/火点打一次高光，字幕起。
**验收**：逐帧看能读出"他递—她接"的顺序；三枚针必须逐枚落下，不能同时出现。

### 3.3 S11/S12「烟花与襄阳城」——换底图 + 换烟花语言

**问题**：v10 是深蓝夜空里一朵**细白线星形**，既不像烟花也不像襄阳；城只是黑剪影一条。
**改**：
- 底图换 `p-fireworks-city`：城墙城楼剪影横贯下方 1/3，砖缝、垛口、灯笼暖点、护城河反光；
- 烟花改"团块语言"：低空一团团火金/赭红爆开（`Fireworks.tsx` 已有），带**烟尾下垂**与**余烬飘落**，每 18–24f 一朵、错峰 3 层景深（远景小、近景大），云被由下往上照亮；
- S12 加入**城中屋脊被照亮**的一段：光从烟花位置扩散到屋顶（片状暖光染色，不是全屏泛白）。
**验收**：静帧要能认出"襄阳城 + 中国烟花"，不是"夜空 + 星芒"。

### 3.4 S15 → S16「十六年」+ 小毛驴

**意见 6（十六年怎么体现）与意见 7（脚印换成小毛驴）合并处理**——它们本就是同一次时间跳跃的两端。

**改**：
- S15 保持（城头空袖背影看城），**出镜用墨洇吞没**；
- S16（150f）内部完成时间流逝：
  - 0–20f 墨团化开，露出土路；
  - 20–104f **三拍季节叠化**（同一构图不动，只换天气与光）：① 春·淡青雾 + 落花 ② 冬·雪覆路 + 飞雪（`DustField` 冷白）③ 秋·枯黄芦苇 + 斜暖光；每拍切换处 6f 十字叠化，并在切换点让画面过曝/压暗一档（模拟年份跳过的快门）；
  - 104–150f 落定在秋：**小毛驴与郭襄的背影**（`p-donkey-road`）在画面偏左、人高 8–12%，镜头**缓慢后拉**（zoom 1.08 → 1.0）让人越走越远，雾气向镜头方向流动；
  - 全段不出字幕以外的任何文字（不出现"十六年后"字样）。
**验收**：连看 S15→S16，观众要能说出"过了很多年"；单看 S16 中段要看到"人 + 驴在走远"。

### 3.5 S17「渡口」——重做

**问题**：v10 的渡口只有一条雾带的岸线与小船，缺"渡口"的实体（栈桥、桩、缆、船、等船的人），所以看不出是渡口。
**改**：底图换 `p-ferry-mist`；镜头语言改为**横移跟拍**（自左向右 40px），她背剑从栈桥走向船头（`XiangFigure` 走路循环 60f，脚步落点与栈板对齐）；水面加横向波纹带（`WaveField` 低频），缆绳随水轻摆；远处对岸两盏船灯暖点。
**验收**：静帧能数出"栈桥 + 渡船 + 缆绳 + 水"四件事。

### 3.6 S19「一个人的雪山」——删雕羽、改独行

**问题**：v10 的重点是"雪地上正在被抹平的脚印 + 一片黑色雕羽落下"，用户读成"叶子"，且情感是"追踪"，不是"孤独"。
**改**：底图换 `p-snow-walk`；**删掉雕羽**与落羽动效；改为：
- 她的背影极小（画面高 8%）走在雪脊上，**朝画面深处走**；
- 慢后拉（zoom 1.06 → 1.0）+ 雪片斜落（风向右 12px/s）；
- 她走过处留一串脚印，最后 30f 新雪把最近两枚脚印盖住（贴片淡入）——"连痕迹也留不住"，孤独感由此而来，而不是靠一片羽毛解释。
**验收**：抽 3 帧（走/远/雪盖脚印），不得出现羽毛状物体。

### 3.7 S20 + S24「茶馆」——把"醒木特写"和"茶棚空镜"合成一个茶馆

**问题**：S20 只有一记醒木，观众不知道这是何处；S24 是一个棚子加一碗茶，无人、无事件，用户直接问"这画面意义是什么"。
**改**（两镜共用底图 `p-teahouse`，机位不同）：
- **S20**（180f）：茶馆全景——说书人在画面右前侧（长衫、侧后、不可见正脸），四周长凳上坐满过客背影，茶烟与窗棂光柱；醒木在 60f 落下（画面轻震 2px + 一声闷响留给混音），落下瞬间**茶烟被震散一下**；她坐在最外圈（左侧、背向镜头、很小）——观众这一眼要认出"她在人群里听别人的故事"。
- **S24**（210f）：同馆另一机位（更近、过肩）——前景虚焦过客肩背做框，中景她把那碗茶喝完（碗从满到空，三段），锣声在 90f（混音），她放下碗、手指在碗沿停 20f。
- 两镜共用一套暖赭色调与茶烟动效，视觉上必须读作"同一个地方"。
**验收**：连看 S20→S24 能说出"茶馆 / 说书 / 她只是个听客"；S24 不得再是空镜。

### 3.8 S21「求揭面」——弃代码剪影，改真图 + 动作

**问题**：v10 用 `YangGuoFigure`/`XiangFigure` 代码剪影，用户读作"两坨黑色"；且这是全片情感顶点，只有两块黑显然撑不住。意见 11 与 13 是同一场。
**改**（210f，底图换 `p-unmask`）：
- 0–50f：她在左前景，举针的手在画面中下部（`f-her-offer` 或底图内已含）；他背影在右侧景，**静**；
- 50–110f：**他抬手**——左手从身侧抬到面具/脸前（4 段关键帧，带动袖口与空袖的滞后摆），抬到一半停住；
- 110–150f：她手里的针**淡出**（针已交出去/或已被他接住），手指仍停在原位；雾从雪脊漫上来，把两人的下半身吃掉；
- 150–210f：手仍举着，面具**没有摘**——她不揭面，观众也不揭；只有雾、雪、他抬起的手。
- 字幕无一字；这段全靠动作与雾。
**验收**：抽 6 帧按序读：她举针 → 他抬手 → 手到面具 → 针不见 → 停 → 雾起。不得出现纯黑剪影块。

### 3.9 S27「晨课里的人」——修「一坨黑色」

**问题**：v10 在弟子队列里塞了一个**纯黑小身影**，与底图人物不同族，读作污点。
**改**：她改为同一画风的**浅灰青背影**（`#7A8A92` 系，受光边 + 半透明压暗），高度从 ~12% 提到 18%，位置在两列弟子之间偏右，走动改用 `XiangFigure` 的慢速步态（0.6× 速度）；**不允许纯黑填充**（`fill: colors.ink` 直填禁用）。
**验收**：抽帧对比：她必须在明度与笔触上和底图弟子同族。

### 3.10 S28「剑入匣」——换动效

**问题**：v10 用 `dry` 干笔擦做"剑滑入匣"，用户"难看死了"：干笔条带是横向几何条，与画面无关。
**改**（210f，底图不变 `p-sword-case`）：
- 0–70f：她把剑从背上解下（剑影沿一条弧线落向桌面，`interpolate` 缓出）；
- 70–120f：剑身**平放入匣**——剑是用"亮度与遮挡"进匣的：先剑影滑到匣口、再被匣沿遮住 60%，最后 8f 完全没入（不画干笔）；
- 120–150f：匣盖合上（匣盖沿铰链转动 12f，落盖时桌上灯焰一晃、一点尘起）；
- 150–210f：静，灯火在匣面上亮一下。
**验收**：不得出现干笔条带/几何蒙版；合匣要有"落"的重量。

### 3.11 S33/S34「案头」——去掉毛笔，整张重做

**问题**：v10 在 S33 用一支**巨大的毛笔刷过画面**（`p-brush`），像素材错误；用户要求去掉、整张重画。
**改**：
- 底图统一换 `p-paper-lamp`（案上纸、灯、笔搁），**画面前景不得出现笔**；
- **S33**（210f）"笔悬着"改为"笔已搁在笔架上"：纸面第五行停在行尾，灯焰跳动（`Objects.tsx` 灯焰 + 光晕呼吸），纸角被穿堂风掀起 2 次，湿墨的高光在灯下慢慢变干；
- **S34**（180f）"一滴墨落下"：砚池边凝起一颗墨珠（代码画，8px→14px），下落 6f，落在第五行行末，`InkBloom` 洇开吃掉那个字（半径 8→90，12f），墨色边缘有渗纸毛刺；
- 两镜共用同一机位与光位，接得上。
**验收**：S33 抽帧不得出现毛笔；S34 的墨滴必须"先凝后落"。

## 四 · 渲染与验收

1. 改动 14 镜：`s09 s10 s11 s12 s15 s16 s17 s19 s20 s21 s24 s27 s28 s33 s34`（+ `s01/s38` 只受墨洇影响）。其余 23 镜不重渲。

## 六 · 鬼帧事故（渲染管线级，2026-11-07）

**现象**：remotion 出来的 mp4 里随机帧整幅变成「画面缩到 1/3、平铺成 3×3 九宫格」；同一帧用 `remotion still` 单渲是干净的，`--concurrency=1 --disable-shared-memory-capture` 后消失。shots-a 在 s11 上实测 8 帧里 4 帧是鬼帧。

**成因**：Chrome 156 + Remotion 并发截图时 shared-memory capture 偶发返回错 surface（拍到一张缩放平铺的中间纹理）。

**处方**（已落地）：
- `scripts/render-film.mjs` 的 `renderMedia` 加 `chromiumOptions: { disableSharedMemoryCapture: true }`，回落 CDP 截图；实测 4/8 鬼帧 → 0。
- 新增 `scripts/check-ghost-frames.py`：把片子解码成 96×54 灰度流，**逐帧全扫**；判据是「相邻三等分逐像素相同（d3 < 1.5）且帧标准差 ≥ 8」——鬼帧的 d3 实测恒为 0.0，正常画面 d3 ≈ 20–30，片头字卡/黑场被 sd 门槛排除。v10 成片实测 7350 帧全扫干净（也说明这条判据不误报）。
- 验收口径加一条：**成片必须过鬼帧全扫**，不许有 1/3 平铺帧。

**教训**：这类"随机坏帧"不能靠抽 8 帧看，必须全扫；产品 mp4 的抽帧自查只能证明"这几帧没问题"。
